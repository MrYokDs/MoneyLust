# Autonomous Build Verification (การทดสอบ Build อัตโนมัติโดยไม่ต้องขออนุญาต)

เอกสารมาตรฐานการรันคำสั่งทดสอบการคอมไพล์และ Type Check ในโปรเจกต์ MoneyLust ที่ได้รับการอนุญาตล่วงหน้า (Pre-authorized) จากผู้ใช้

---

## 1. ที่มาและบริบท (Context & Origin)
- **คำสั่งของผู้ใช้**: *"ครั้งหน้าหากคุณต้องการ run คำสั่ง yarn build สำหรับโปรเจคนี้คุณสามารถ run ได้เลย ไม่ต้องขออนุญาติฉันแล้ว"*
- **เป้าหมาย**: เพิ่มความรวดเร็วในการพัฒนา ลดขั้นตอนการถาม-ตอบที่ไม่จำเป็น และคงไว้ซึ่งคุณภาพความถูกต้องของซอร์สโค้ด 100%

---

## 2. เหตุผลและความสำคัญ (Rationale)
1. **ความถูกต้องของระบบ (Code Reliability)**: โปรเจกต์ใช้ TypeScript ร่วมกับ React และ Material UI การรัน `yarn build` (`tsc -b && vite build`) เป็นวิธีเดียวที่การันตีได้ว่าไม่มีข้อผิดพลาดด้าน Type, Syntax, หรือปัญหา Bundling หลงเหลืออยู่
2. **การทำงานแบบอัตโนมัติราบรื่น (Zero Friction)**: ตัวแทน AI มีสิทธิ์ทำงานเชิงรุก (Autonomous) ในการทดสอบและแก้ไขข้อผิดพลาดด้วยตนเองทันที โดยไม่ต้องรอรอบการถาม-ตอบเพื่อขออนุญาตรันคำสั่ง Build

---

## 3. ระเบียบปฏิบัติมาตรฐาน (Standard Procedure)

### กฎปฏิบัติ:
1. **รันได้ทันทีหลังแก้ไขโค้ด**:
   - เมื่อใดก็ตามที่มีการสร้างไฟล์ใหม่ แก้ไขโค้ด หรือ Refactor โค้ดในโปรเจกต์ ให้เรียกใช้ Tool `run_command` เพื่อรันคำสั่ง Build ทันที
   - **ไม่ต้องสอบถามผู้ใช้** ก่อนรันคำสั่งนี้
2. **รูปแบบคำสั่งที่ถูกต้องบน Windows**:
   - เพื่อป้องกันปัญหาข้อจำกัดสิทธิ์ของ Windows PowerShell (Execution Policy) ให้รันผ่าน CMD เสมอ:
     ```bash
     cmd /c "yarn build"
     ```
3. **การประเมินผลลัพธ์**:
   - หากคำสั่งคืนค่า `Exit code: 0` แสดงว่าการคอมไพล์ผ่านสมบูรณ์ สามารถดำเนินงานต่อหรือส่งมอบงานได้
   - หากพบข้อผิดพลาด (Type error, import error, syntax error) ให้วิเคราะห์และทำการแก้ไขโค้ดทันที จากนั้นรัน `cmd /c "yarn build"` ซ้ำจนกว่าจะผ่านทั้งหมดก่อนตอบผู้ใช้

---

## 4. รายการตรวจสอบ (Checklist)
- [ ] มีการแก้ไขหรือสร้างโค้ดใหม่เสร็จสิ้นแล้วหรือไม่
- [ ] สั่งรัน `cmd /c "yarn build"` ทันทีโดยไม่ต้องถามขออนุญาต
- [ ] ตรวจสอบว่าผลลัพธ์ Exit Code เป็น 0 (ไม่มี Type Error)
- [ ] หากมี Error ให้แก้ไขทันทีแล้วรันซ้ำจนผ่าน
