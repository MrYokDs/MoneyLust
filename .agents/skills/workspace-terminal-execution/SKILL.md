# Autonomous Workspace Terminal Execution (มาตรฐานการรันคำสั่ง Terminal อัตโนมัติภายใน Workspace)

## 1. บริบทและสิทธิ์ที่ได้รับอนุญาต (Context & Authorization)
- **การอนุญาตจากผู้ใช้ (Explicit User Authorization)**: ผู้ใช้ได้ให้สิทธิ์อย่างเป็นทางการแก่อัจฉริยะ (Agent) ในการเรียกใช้ Terminal หรือรันคำสั่งผ่านเครื่องมือ `run_command` เพื่อทดสอบ ตรวจสอบ หรือประมวลผลงานใดๆ ในโปรเจกต์นี้ได้ทันทีโดยอัตโนมัติ ไม่ต้องหยุดรอหรือถามขออนุญาตผู้ใช้ก่อนทุกครั้ง
- **ขอบเขตความปลอดภัยเข้มงวด (Strict Security Boundary)**:
  - การทำงานทั้งหมด **ต้องอยู่ภายใน Workspace ของโปรเจกต์นี้เท่านั้น** (`f:\All_Works\Programming\React_Programming\MoneyLust`)
  - **ห้าม (STRICTLY FORBIDDEN)**: ห้ามสั่งรันคำสั่งที่เข้าถึง แก้ไข ลบ หรือเปลี่ยนแปลงไฟล์/ไดเรกทอรีใดๆ ภายนอก Workspace (ห้ามยุ่งกับไดรฟ์อื่น โฟลเดอร์ระบบ หรือ Desktop/Downloads ของเครื่องผู้ใช้)

---

## 2. คำสั่งที่ได้รับอนุญาตให้รันอัตโนมัติ (Pre-Authorized Command Patterns)
1. **Build & Type Checking**:
   - `cmd /c "yarn build"` (ทดสอบคอมไพล์ Vite + TypeScript)
   - `npx tsc --noEmit`
2. **Testing & Linting**:
   - `cmd /c "yarn test"`
   - `npx eslint ...`
3. **Workspace Inspection & Verification**:
   - `git status`, `git diff`, `git log` (จำกัดความยาว)
   - `powershell -Command "..."` เพื่อตรวจนับจำนวนบรรทัดของไฟล์ (`Length`) หรือคำนวณสถิติภายในโปรเจกต์
   - `node -e "..."` เพื่อคำนวณสูตรหรือทดสอบ Math logic ก่อนนำไปใช้งานจริง
4. **Package Management (เมื่อจำเป็นและสอดคล้องกับงาน)**:
   - `yarn install`, `yarn add <package>` (เมื่อผู้ใช้มอบหมายงานที่ต้องใช้ไลบรารีใหม่)

---

## 3. กฎเหล็กในการรันคำสั่ง (Mandatory Rules)
1. **กำหนด `Cwd` ให้อยู่ภายใน Workspace เสมอ**:
   - พารามิเตอร์ `Cwd` ใน `run_command` ต้องชี้ไปที่โฟลเดอร์ของโปรเจกต์ MoneyLust เสมอ
2. **ห้ามใช้คำสั่ง `cd`**:
   - ห้ามสั่งคำสั่ง `cd` ใน CommandLine ให้กำหนดผ่านพารามิเตอร์ `Cwd` แทน
3. **ห้ามสั่งคำสั่งที่เสี่ยงต่อข้อมูลสูญหาย (Data Loss Prevention)**:
   - ห้ามรัน `rm -rf`, `git clean -fdx`, `git reset --hard` หรือคำสั่งลบโค้ด/ไฟล์โดยเด็ดขาด เว้นแต่ผู้ใช้จะสั่งการอย่างชัดเจนเป็นรายครั้ง (สอดคล้องกับ Rule 7)
4. **ตรวจสอบผลลัพธ์ Exit Code**:
   - ทุกครั้งที่รันคำสั่ง ต้องตรวจสอบว่า Exit code เป็น `0` หรือไม่ หากมี Error ต้องรีบแก้ไขให้เรียบร้อยก่อนจบ Turn
